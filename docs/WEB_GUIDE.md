# 网页使用说明

这里汇总 Multiple_Video_Downloader 网页界面中的常用操作、下载格式、任务状态和问题处理方式。

## 开始使用

确认项目网页已经启动后，在浏览器访问 [http://127.0.0.1:8233](http://127.0.0.1:8233)。页面显示后即可分别提交视频或音频任务。

> 网页和系统文件夹选择器仅面向运行本项目的本机桌面会话。浏览器不会读取或上传任意本机目录内容。

## 下载操作流程

1. 下载视频时，在 **最高画质视频** 区块粘贴链接或平台分享文案；只需要音频时，在 **最高音质音频** 区块操作。多个链接一行一个。
2. 音频可选 **MP3 V0**、**源 FLAC**、**原始音轨**或 **WAV PCM**。WAV 文件较大且不会提升源音质；源站没有 FLAC 时，源 FLAC 会自动回退至 MP3 V0。
3. 在 **下载位置** 中手动输入路径，或点击 **选择文件夹** 打开 Windows/macOS 系统选择器；留空则继续使用页面提示的默认 `downloads/`。
4. 下载位置右侧的下拉按钮会保留当前浏览器最近成功使用的 3 个目录。相同路径自动去重，最近使用的排在最上方。
5. 单条内容会直接提交；播放列表、合集与分 P 会先显示预览面板。一次最多选择 100 项。
6. 点击下载后，可在下载任务区查看排队、速度、预计剩余时间、进度、处理阶段、输出规格及保存路径。

## 视频、音频与文件输出

- 视频会选择源站可获取的最高质量视频流和音频流，并由 FFmpeg 合并为 MP4。
- MP3 V0 会先选择最高质量源音轨，再用 FFmpeg 进行最高 VBR 品质转换。
- 源 FLAC 只在源站确实提供 FLAC 时直接输出，不会把 AAC 或 Opus 伪装成无损音频。
- 原始音轨保留源编码和相应扩展名；WAV 是解码后的 PCM，文件较大但不会提高源质量。
- MP3、FLAC 和部分支持封面的容器会尝试嵌入视频封面；WebM 与 WAV 正常输出但不嵌入封面。
- 重复下载不会覆盖旧文件，新文件使用 `(2)`、`(3)` 等递增后缀。

## 下载位置与历史记录

- 留空：保存到项目默认的 `downloads/` 文件夹。
- 手动输入：可输入 Windows 或 macOS 上可创建、可写的文件夹路径。
- 系统选择器：点击 **选择文件夹**，在运行 Web 服务的电脑上选择目录。
- 最近位置：只在下载请求成功提交后记录；取消选择、无效路径或提交失败不会写入历史。
- 历史数据只保存在当前浏览器的本地存储中，不会上传；清除浏览器站点数据后会同时清除。
- 重试和重新下载会继续使用原任务的下载位置，不会自动退回默认目录。

## 任务队列与操作

- 所有 Web 批次共用最多 3 个工作槽，其中 Bilibili 最多同时运行 2 项。
- **取消**：等待任务立即取消；标准下载会在下一个安全检查点停止。
- **重试**：失败或已取消任务重新进入同一队列，并保留每一次尝试记录。
- **重试全部失败项**：只重新提交可重试的失败任务。
- **重新下载**：对已完成任务创建新任务，并保留原文件。
- 服务在内存中最多保留 100 个批次。重启 Web 服务后页面任务历史清空，但已下载文件不会删除。

## Bilibili 极速模式

- 极速模式需要系统或项目本地存在 `aria2c`；未检测到时开关会自动禁用。
- 该模式只用于 Bilibili，YouTube 和 Instagram 不使用 aria2c。
- 大于 50 MiB 的选中流可能在 Bilibili 返回的最多 4 个 HTTPS CDN 主机间进行小样本测速。
- 进入“不可中断”状态后不提供取消按钮，需要等待该任务完成。
- aria2c 失败或 CDN 返回 `HTTP 403` / `HTTP 412` 时，项目会自动切换回标准模式或原始 CDN。
- 加速不会绕过平台权限、风控或限速，实际速度仍取决于地区、网络路由和 CDN 负载。

## 支持的链接

| 平台 | 支持的常见页面 |
|---|---|
| YouTube | 标准视频、短链接、Shorts、直播/回放、嵌入视频、YouTube Music、播放列表 |
| Instagram | Reels、视频帖子、IGTV、有效期内且当前账号可访问的 Stories |
| Bilibili | BV、av、移动端视频、指定分 P、多分 P、list、medialist、UP 主合集、b23.tv 短链接 |

能否展开播放列表、合集或分 P，仍取决于页面公开状态、yt-dlp 支持情况和当前 Cookie 权限。需要 DRM、额外业务接口或当前账号无权访问的内容不会被绕过。

## 登录内容与 Cookie

公开内容通常无需 Cookie。私密内容、年龄限制内容或平台明确要求登录的内容，需要当前账号本来就有权访问，并在项目根目录放置 Netscape 格式的 Cookie 文件：

| 平台 | 文件名 |
|---|---|
| YouTube | `youtube_cookies.txt` |
| Instagram | `instagram_cookies.txt` |
| Bilibili | `bilibili_cookies.txt` |

建议使用开源扩展 **Get cookies.txt LOCALLY**，并仅从官方页面安装：

- [Chrome / Edge 安装页面](https://chromewebstore.google.com/detail/get-cookiestxt-locally/cclelndahbckbenkjhflpdbgdldlbecc)
- [Firefox 安装页面](https://addons.mozilla.org/en-US/firefox/addon/get-cookies-txt-locally/)
- [源代码与隐私说明](https://github.com/kairi003/Get-cookies.txt-LOCALLY)

导出时只导出当前平台域名，选择 Netscape 格式，并确认首行包含 `# Netscape HTTP Cookie File`。保存到项目根目录并使用上表文件名后，重启 Web 服务并刷新页面。

> Cookie 文件等同于登录凭证。不要上传、分享、截图、提交到 Git，或粘贴到聊天、Issue 和日志中。

## 常见问题

| 问题 | 处理方式 |
|---|---|
| 页面打不开 | 确认 Web 服务正在运行，然后访问 `http://127.0.0.1:8233` |
| 未检测到 FFmpeg | 安装 FFmpeg、加入系统 PATH，重新打开终端并重启 Web 服务 |
| 未检测到 aria2c | 可继续使用标准模式；安装 aria2c 后重启 Web 服务 |
| HTTP 403 或要求登录 | 确认浏览器账号有权播放目标内容，再更新对应平台 Cookie |
| HTTP 429 | 请求过于频繁，暂停一段时间后再试 |
| Bilibili HTTP 412 | 降低请求频率，稍后重试；登录内容同时更新 Bilibili Cookie |
| 网络连接超时 | 检查本机网络、代理或 VPN 配置后重试 |
| 下载后没有声音或无法合并 | 确认 FFmpeg 已安装并可被项目找到 |
| 文件夹不可写 | 选择普通用户具有写入权限的目录，不要直接选择 Windows 系统保护目录 |
| 进度出现乱码或旧样式 | 重启 Web 服务并使用 `Ctrl+F5` 强制刷新页面 |
