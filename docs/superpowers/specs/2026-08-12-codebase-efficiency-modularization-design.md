# 代码效率与模块化重构设计

## 背景

当前项目功能完整且测试基线稳定，但复杂度集中在 `downloader.py` 与
`templates/index.html`。本轮优化不增加下载平台或输出格式，只在保持 Web、CLI、
文件命名、并发上限、错误码和用户下载文件不变的前提下，减少重复 I/O、降低前端
轮询成本，并把高耦合代码拆到职责明确的模块。

## 目标

1. 防止 Web 状态轮询请求重叠和旧响应覆盖新状态。
2. 避免同一批次为每个任务重复创建下载目录写入探测文件。
3. 及时释放已完成任务持有的 `Future` 与取消令牌，限制长期内存增长。
4. 将首页 CSS 与 JavaScript 从巨型模板拆成可缓存的静态资源。
5. 渐进拆分 `downloader.py`，优先抽离平台解析、输出文件和音频输出职责。
6. 统一普通平台与 Bilibili 的输出收尾和结果组装，减少分支漂移。

## 非目标

- 不改变最高画质、音质选择、FLAC 回退、aria2、CDN 或 Cookie 策略。
- 不改变全局最多 3 个任务、Bilibili 最多 2 个任务的并发限制。
- 不把前端改造成框架项目，不引入 Node 构建工具或新的运行时依赖。
- 不删除可能被外部脚本使用的兼容函数。
- 不并行化合集元数据解析；该项收益与平台限流风险暂不匹配。

## 设计

### 1. Web 轮询

用“请求完成后再调度下一次”的递归 `setTimeout` 取代 `setInterval`。轮询器维护单一
计时器与请求序号，同一时刻最多一个状态请求。页面不可见时使用较长间隔，重新可见
时立即刷新。前端记录最近一次批次内容签名；任务状态无变化时不重建任务列表 DOM，
但仍更新必要的计时与控制状态。

本轮不引入 SSE/WebSocket，也不改变 `/api/batch/<id>` 的响应格式。

### 2. 下载目录验证

保留 `ensure_downloads_dir()` 作为外部输入边界的完整解析、创建和可写性验证函数。
新增一个内部轻量路径准备接口，供已经完成边界验证的批次任务使用。Web 和 CLI 在创建
批次前只执行一次完整验证，随后向任务传递绝对 `Path`；单独调用公共 `download_video()`
时仍执行完整验证，以保留公共 API 的安全性。

任务管理器向下载器传递一个明确的“目录已验证”内部标志，而不是依赖类型猜测。真正
写文件时的 `OSError` 继续转换为现有结构化错误。

### 3. 任务和预览生命周期

任务进入终态后立即从 `_futures` 与 `_tokens` 删除；generation 保留到批次淘汰，用于
拒绝过期回调。公开任务历史最多返回最近 20 次尝试，同时保留总 `attempt_count`。

`PreviewStore` 增加容量上限，`put()` 与 `get()` 都清理过期条目；超过容量时淘汰最早
到期的预览。默认容量与现有批次数量同阶，避免无界增长。

### 4. 前端资源边界

将首页内联样式移动到 `static/css/index.css`，交互逻辑移动到
`static/js/index.js`，并用 `defer` 加载。HTML 暂时保留现有内联事件属性；脚本明确将
这些处理函数暴露到 `window`，以保持行为兼容。拆分后不引入打包器，Flask 继续通过
`url_for('static', ...)` 生成资源地址。

### 5. 后端模块边界

按以下顺序渐进抽离，`downloader.py` 暂时重新导出公共名称以兼容现有调用者：

- `media_sources.py`：URL 标准化、平台/合集识别、Cookie 与平台请求头。
- `download_progress.py`：进度格式、后处理阶段文案与 yt-dlp hooks。
- `audio_output.py`：音频 profile、格式选择、后处理器与质量标签。
- `output_files.py`：目录验证、尝试工作区、输出定位、原子命名与版本号。

Bilibili 下载编排本轮保留在 `downloader.py`，避免同时移动重试状态机与底层工具造成
过大风险；但普通平台和 Bilibili 必须共用输出收尾及结果构造 helper。

### 6. 校验策略

保留 Web、CLI 与公共 Python API 边界校验。把枚举校验集中到共享 helper，内部私有
函数接收已验证参数。只取消会产生实际 I/O 的重复目录探测，不为省略几次集合查找而
削弱防御性校验。

环境探测 `node` 与 `aria2c` 使用进程级缓存，并保留显式刷新入口供测试与服务重启流程
使用。

## 数据流

1. Web/CLI 输入边界完成 URL、选项与下载目录验证。
2. 批次保存已验证的绝对下载路径。
3. TaskManager 在既有并发约束下调用下载编排层。
4. 下载编排层调用平台、进度、音频和输出文件模块。
5. TaskManager 记录精简公共状态；前端串行轮询并只更新变化内容。

## 错误处理与兼容性

- 保持现有结构化错误码、中文建议和日志脱敏逻辑。
- 保持 `downloader.py` 的公共常量、类型和兼容函数可导入。
- 保持所有最终文件名、封面、质量后缀与防覆盖规则。
- 不删除或修改 `downloads/` 中的任何既有文件。
- 模块移动若出现循环依赖，公共常量下沉到无副作用的共享模块，禁止通过延迟导入掩盖。

## 测试与验收

每个行为变化先写失败测试，再实现：

1. 前端轮询同一时刻只有一个请求，隐藏页面使用慢间隔，无变化不重建任务 DOM。
2. 100 项批次只做一次目录写入探测；直接调用 `download_video()` 仍完整验证。
3. 终态任务释放 Future/Token，公开尝试历史最多 20 项，预览缓存有容量上限。
4. 首页通过外部 CSS/JS 正常加载，所有既有 UI 文案与控件仍存在。
5. 模块抽离后公共导入、Web、CLI、Bilibili、音频与文件命名测试全部保持通过。
6. 完整测试、`compileall`、JavaScript 语法检查和浏览器桌面/移动 QA 通过。
7. 优化前后 `downloads/` 文件数量与 SHA-256 清单完全一致。

## 实施顺序

1. 串行、自适应 Web 轮询。
2. 单次下载目录完整验证。
3. 任务与预览生命周期收敛。
4. 首页静态资源拆分。
5. 平台解析与输出文件模块拆分。
6. 进度与音频模块拆分、统一下载收尾。
7. 完整回归、实际 Web QA 与独立代码复审。
