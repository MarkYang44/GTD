# 任务控制、合集下载、音频输出与结构化错误设计

## 目标

在不改变现有最高画质下载、Bilibili 加速策略和并发边界的前提下，为 Web 下载流程增加取消、重试和重新下载能力；支持 YouTube 播放列表、Bilibili 合集/系列/分 P，以及提取器能够识别的 Instagram 多媒体帖子；新增原始音频和 WAV 输出；用稳定错误码和脱敏轮转日志替代笼统的“下载失败”。

浏览器扩展不在本轮实现范围内，但本轮接口与模块边界必须允许后续安全接入。

## 非目标

- 不恢复此前放弃的画质或音质档位选择，视频仍下载源站可获取的最高画质。
- 不引入 SQLite、Redis、独立 Worker 或跨进程持久化任务队列。
- 不保证服务重启后恢复未完成任务或历史任务。
- 不支持整个 YouTube 频道、Bilibili 用户空间、私人收藏夹、稍后再看或 Instagram 用户主页的全量抓取。
- 不把有损源转换成 WAV 后描述为“无损升级”。
- 不改变 aria2c 极速任务的执行模型；任务一旦进入 aria2c 传输阶段便不可取消。
- 不在本轮创建或发布浏览器扩展。

## 已确认决策

- 采用模块化增量升级，保留 Flask、本地内存状态和现有下载核心。
- 排队任务可立即取消；标准下载任务采用进度回调处的协作式取消。
- aria2c 极速任务开始后不提供取消，直接运行到完成或失败。
- 失败或已取消任务在原任务卡片上重试，保留尝试历史并增加尝试次数。
- 已完成任务重新下载时创建新任务，保留原文件，并给新文件追加 `(2)`、`(3)` 等序号。
- 合集先解析预览，再由用户勾选全部或部分条目；单次最多提交 100 项。
- 音频输出包括 MP3 V0、源 FLAC、原始音频和 WAV。
- 日志采用自动轮转的 JSONL 文件，网页展示结构化错误码、中文原因和处理建议。
- 继续维持最多 3 个全局下载任务、最多 2 个 Bilibili 下载任务。

## 当前基线与兼容性

- `downloader.py` 是 Web 与 CLI 共用的下载核心，负责平台识别、格式选择、yt-dlp/FFmpeg 配置、Bilibili CDN 与 aria2c 降级。
- `app.py` 维护内存批次和任务状态，通过后台线程调用 `download_tasks()`。
- `/api/download` 接收 URL、媒体类型、速度模式和音频格式；`/api/batch/<batch_id>` 返回轮询状态。
- 当前音频格式为 MP3 V0 与源 FLAC。源站不提供真实 FLAC 时按既有规则回退到 MP3 V0。
- 未传递新增参数的现有 Python、CLI 和 Web 调用必须保持当前默认行为。
- `downloads/` 中已有文件不得被测试、取消清理、重试或重新下载逻辑删除或覆盖。

## 总体架构

保留现有 Flask 与下载器，增加四个职责明确的模块：

- `task_control.py`：任务状态机、取消令牌、尝试历史、重试、重新下载和统一调度。
- `collection_resolver.py`：链接清洗、单项/合集识别、只读元数据解析、预览条目与选择校验。
- `download_errors.py`：异常分类、错误对象、中文建议和可重试属性。
- `download_logging.py`：JSONL 轮转日志、上下文字段与敏感信息脱敏。

`downloader.py` 继续负责单个媒体任务的真实下载，并增加取消令牌、输出版本与新音频格式参数。CLI 的 `download_tasks()` 保持为共享批量入口；Web 由进程内 `TaskManager` 统一调度单项任务，避免取消、重试或同时存在多个批次时绕过全局并发限制。

数据流如下：

`输入文本 -> 提取并标准化链接 -> 识别单项或合集 -> 合集元数据预览 -> 勾选条目 -> 创建任务 -> 全局调度 -> 下载/后处理 -> 结果与结构化日志`

## 任务模型与调度

### 状态

任务状态统一为：

- `queued`：已入队，尚未占用下载工作线程。
- `running`：标准任务正在下载或后处理。
- `running_uninterruptible`：aria2c 极速传输已经开始，不可取消。
- `completed`：最终文件已完整生成。
- `failed`：当前尝试失败。
- `cancelled`：取消请求已被安全执行。

允许的主要转换为：

- `queued -> running -> completed | failed | cancelled`
- `queued -> cancelled`
- `running -> running_uninterruptible -> completed | failed`
- `failed | cancelled -> queued`，表示在同一任务上重试。

终态计数由任务当前状态重新计算，不继续依赖容易在重试时重复累加的完成/失败计数。批次状态同时返回活动、排队、完成、失败和取消数量；所有任务进入 `completed`、`failed` 或 `cancelled` 后标记 `all_done`。

### 任务与尝试记录

每个任务至少包含：

- `id`、`batch_id`、标准化 URL、平台、标题和合集序号。
- `media_type`、`audio_format`、`speed_mode` 和输出版本。
- 当前状态、进度、是否可取消、取消请求标记。
- `attempt_count` 与 `attempts`。每次尝试记录开始/结束时间、终态、错误对象和实际输出路径。
- 最近一次错误和实际使用的下载/音频模式。

`TaskManager` 持有一个 `ThreadPoolExecutor(max_workers=3)`，并复用现有 Bilibili 最大 2 项的并发限制。任务重试和重新下载必须回到同一调度器，不另起不受控的线程池。

## 取消机制

### 排队任务

排队任务立即转为 `cancelled`，不会进入下载器，也不会产生临时文件。已提交到执行器但尚未运行的 Future 在可以安全取消时同步取消；不能取消 Future 时，工作函数启动后首先检查令牌并立即退出。

### 标准下载任务

每个任务持有线程安全的 `CancellationToken`。下载器在开始前、yt-dlp 进度回调、后处理回调和主要阶段切换处检查令牌。检测到取消后抛出项目内专用取消异常，并将任务标记为 `cancelled`，而不是 `failed`。

协作式取消不是强制终止子进程：在 FFmpeg 合并等缺少安全回调的短暂阶段，取消可能延迟到下一个检查点。如果完整文件在取消被观察前已经原子完成，则完成状态优先，避免删除有效成品。

清理仅针对当前尝试明确创建的 `.part`、临时缩略图、临时转码和中间合并文件。不得使用宽范围通配删除，也不得删除运行前已经存在的任何文件。

### aria2c 极速任务

任务进入 aria2c 媒体传输前仍可从队列取消；一旦传输启动，状态改为 `running_uninterruptible`，Web 隐藏取消按钮并显示“极速任务不可取消”。该任务继续执行至完成、失败或按既有逻辑降级为标准模式。

若 aria2c 在同一次尝试中自动降级为标准模式，仍不重新开放取消按钮，避免用户误判当前尝试的执行边界。

## 重试与重新下载

### 重试

- 仅 `failed` 和 `cancelled` 任务可重试。
- 重试复用原任务 ID 和任务卡片，保留原参数与全部尝试记录，`attempt_count` 加一后重新进入 `queued`。
- 若失败原因不可重试，例如无效 URL、平台不支持或明确的会员权限限制，Web 不显示重试按钮，只显示处理建议。
- 批次提供“重试全部失败任务”，只重置当前仍为 `failed` 且 `retryable=true` 的任务；不会重复提交已完成或已取消任务。
- yt-dlp 自带网络重试继续保留；应用层手动重试不会偷偷自动创建额外任务。

### 重新下载

- 仅 `completed` 任务显示“重新下载”。
- 重新下载创建新的任务 ID，并复制原任务的 URL、媒体类型、音频格式和速度模式。
- 在同一下载目录内，以锁保护的文件名分配器选择下一个可用序号：原文件存在时依次使用 `(2)`、`(3)`。
- 序号插入最终质量标签之后、扩展名之前，并在下载选项和最终重命名阶段保持一致，防止 yt-dlp 因同名文件而跳过。
- 并发重新下载同一内容时也必须分配不同文件名；绝不覆盖原文件。

## 播放列表、合集与分 P

### 支持范围

- YouTube 播放列表。
- Bilibili 合集、系列和多分 P 视频。
- Instagram 单个帖子中由当前 yt-dlp 提取器识别出的多个媒体条目。
- `b23.tv` 短链接，以及“标题 + URL”等平台分享文案，继续先清洗再解析。

私人收藏夹、稍后再看、整个频道/用户空间和无限历史抓取不在本期范围。

### 解析与预览

`collection_resolver` 使用 yt-dlp 的只读、平坦提取能力获取元数据，不下载媒体。普通单项链接直接进入现有提交路径；合集返回临时 `preview_id` 和按原顺序排列的条目：

- 稳定条目 ID、标题、平台、标准链接、序号和缩略图。
- 是否可选择；不可选择时包含结构化原因。
- 合集标题、已解析条目数和预览过期时间。

Bilibili 分 P 条目生成包含明确分 P 标识的标准链接，避免所有任务重复下载第一 P。失效、私密、地区或会员限制条目在预览中禁用，但不阻止其他条目提交。

预览状态只存于内存并定期过期；批次仅保存用户实际选择的任务。网页对预览列表分页或虚拟化展示，避免大型列表一次渲染造成卡顿。

### 选择与提交

- 用户可全选、取消全选或逐项勾选。
- 一次提交至少 1 项、最多 100 项；超过时返回明确校验错误并提示分批提交。
- 视频区解析出的条目继承视频模式和该区极速设置。
- 音频区解析出的条目继承当前音频格式和该区极速设置。
- 条目作为独立任务加入同一批次，保持原顺序；单项失败不终止整批。

## 音频输出

音频格式枚举扩展为：

- `mp3`：默认 MP3 V0，保持现有封面、质量标签和文件命名行为。
- `flac`：仅保存源站真实提供的 FLAC；没有 FLAC 时继续回退 MP3 V0，并明确记录请求格式与实际格式。
- `source`：选择最佳可用音轨，不进行有损重编码。音频独立流直接保留；只有复用容器确实需要时才无损重封装音频流。成品可能为 M4A、WebM、Opus 或 FLAC。
- `wav`：把最佳可用源音频解码为 PCM WAV。界面和结果不得暗示源音质获得提升。

原始音频必须优先选择纯音频流；平台只提供带视频的复用流时，可使用 FFmpeg 以 `-vn` 和音频流复制方式提取到兼容容器，不做有损转码。若无法在不转码的情况下生成有效音频文件，返回 `FORMAT_UNAVAILABLE`，不静默改用 MP3。

封面与元数据在目标容器支持且不会导致音频重编码时继续嵌入；不可靠支持封面的原始容器或 WAV 可以跳过封面，并在结果信息中说明。音频文件名继续标注真实成品格式、源编码和可获得的源码率，不猜测采样率或位深。

## 结构化错误

失败对象统一为：

```json
{
  "error_code": "NETWORK_TIMEOUT",
  "message": "连接源站超时",
  "suggestion": "请检查网络或代理设置后重试",
  "retryable": true,
  "technical_detail": "仅写入脱敏日志"
}
```

首批错误码包括：

- `INVALID_URL`、`UNSUPPORTED_PLATFORM`
- `COLLECTION_EXTRACT_FAILED`、`METADATA_FAILED`、`FORMAT_UNAVAILABLE`
- `AUTH_REQUIRED`、`MEMBERSHIP_REQUIRED`、`GEO_RESTRICTED`
- `NETWORK_TIMEOUT`、`RATE_LIMITED`
- `DOWNLOAD_FAILED`、`ARIA2_FAILED`
- `POSTPROCESS_FAILED`、`STORAGE_ERROR`
- `CANCELLED`

异常分类器优先使用异常类型和已知结构化信息；只有下层库没有稳定类型时才对经过规范化的错误文本做有限匹配。未知异常统一映射到 `DOWNLOAD_FAILED` 或对应阶段的通用错误，原始技术详情只进入日志。

Web 显示错误码、中文原因和建议，不展示堆栈、Cookie 路径或带签名媒体 URL。CLI 使用同一错误对象输出，保证两种入口语义一致。

## JSONL 日志

日志写入 `logs/downloader.jsonl`：

- 单文件最大 10 MiB，保留当前文件和 5 个历史文件。
- 每行是一个独立 JSON 对象，至少包含时间、事件、批次 ID、任务 ID、尝试次数、平台、媒体/音频格式、速度模式、耗时、终态和错误码。
- Cookie 内容、授权头、Token、代理用户名/密码永不记录。
- 页面 URL 只保留平台、主机和内容标识，移除查询参数；媒体 CDN 只记录主机名。
- 日志写入失败不得导致下载失败，只向终端给出一次安全警告。
- `logs/` 加入 Git 忽略，不提交用户运行日志。

## Web 接口与页面

### 接口

新增或扩展以下接口：

- `POST /api/preview`：清洗输入并解析单项或合集；合集返回 `preview_id` 和条目。
- `POST /api/download`：保留现有 URL 提交方式，并允许使用 `preview_id + selected_entry_ids` 创建批次。
- `POST /api/batch/<batch_id>/task/<task_id>/cancel`
- `POST /api/batch/<batch_id>/task/<task_id>/retry`
- `POST /api/batch/<batch_id>/task/<task_id>/redownload`
- `POST /api/batch/<batch_id>/retry-failed`
- `GET /api/batch/<batch_id>`：增加取消能力、尝试次数、错误对象和操作权限字段。

所有修改接口验证批次与任务归属、当前状态和字段类型。对状态冲突返回 HTTP 409，对无效输入返回 400，对不存在资源返回 404。aria2c 运行中的取消请求返回 409 和结构化说明。

### 页面

- 视频与音频继续使用独立输入区，不合并输入框。
- 检测到合集时先显示预览面板，包含缩略图、标题、序号、可选状态、全选和已选数量。
- 音频区显示 `MP3 V0 / 源 FLAC / 原始音频 / WAV` 四项选择。
- 任务卡根据状态展示取消、重试或重新下载按钮；aria2c 运行后显示不可取消提示。
- 批次标题区增加“重试全部失败任务”。
- 失败任务显示结构化错误码、中文原因和建议；尝试历史默认折叠，用户可展开查看每次状态与时间。
- 保持现有深色主题、字体系统、响应式布局和滚动动画，不进行无关视觉重构。

## CLI

CLI 共享新增音频格式、合集解析、错误对象和日志，但不复制 Web 卡片式任务历史：

- 新增可扩展参数 `--audio-format mp3|flac|source|wav`；现有 `--audio --flac` 继续作为兼容别名。
- 交互模式选择音频后显示四种格式。
- CLI 检测到合集时先打印编号预览，并在交互终端接受 `all` 或 `1,3-5` 等选择，最多 100 项。
- 非交互调用合集时必须显式传递条目选择参数，避免脚本意外下载整个列表。
- Ctrl-C 继续终止当前 CLI 运行；Web 专用的重试和重新下载接口不强行映射为 CLI 历史会话。
- CLI 与 Web 使用相同错误码、中文建议和日志脱敏规则。

## 浏览器扩展后续工作

推荐先实现 Chrome/Edge Manifest V3 扩展，后续独立立项：

1. 创建独立扩展目录，包含 Manifest、弹窗、设置页、Service Worker 和图标资源。
2. 使用 `activeTab` 读取当前页面 URL，在弹窗中选择视频、MP3 V0、源 FLAC、原始音频、WAV 和极速模式。
3. 增加右键菜单“发送到 Multiple Video Downloader”和任务完成/失败通知。
4. 后端增加扩展专用健康检查、配对、预览、提交和只读状态接口。
5. CORS 只允许扩展自身 Origin；首次使用生成本地配对令牌，令牌存于扩展本地存储，不放入页面 URL。
6. 检测 `127.0.0.1:8233` 服务未启动时显示安装、启动和端口排查指引。
7. 准备最小权限说明、隐私政策、商店截图、版本更新与打包流程。
8. Safari 版本需要 Xcode 转换、Apple Developer 签名和审核；Firefox 版本需要适配 Manifest 与权限差异。

扩展不能独立替代本地服务：yt-dlp、FFmpeg、Cookie 和下载目录仍由本机后端管理。本轮接口使用稳定错误对象和明确任务操作，为后续扩展复用做准备，但不提前开放宽泛 CORS。

## 测试与验收

### 自动化测试

- 任务状态转换、终态计数、排队取消、标准任务协作取消和完成优先规则。
- aria2c 进入传输后不可取消，失败后仍可重试，现有自动降级不重复产生终态。
- 重试复用任务、增加尝试次数、保留历史；批量重试只选择可重试失败项。
- 重新下载在单线程和并发场景下生成 `(2)`、`(3)`，不覆盖既有文件。
- 取消清理只删除当前尝试明确拥有的临时文件。
- YouTube 播放列表、Bilibili 合集/分 P、Instagram 多媒体条目的顺序、标准链接、禁用项和 100 项限制。
- MP3、真实源 FLAC、原始音频、复用流无损提取和 WAV 的格式选择与后处理参数。
- 错误分类、未知异常回退、HTTP 状态、中文建议和 `retryable`。
- JSONL 字段、10 MiB 轮转、查询参数/Cookie/Token/代理凭据脱敏和日志失败容错。
- Flask 预览、选择提交、取消、重试、重新下载、批量重试与轮询接口。
- CLI 新音频参数、兼容 `--flac`、合集选择和非交互安全边界。
- 现有最高画质、封面、Bilibili CDN/aria2、最大 3/2 并发和文件命名测试全部继续通过。

### 真实与页面验证

- 对可合法访问的 YouTube、Instagram、Bilibili 单项及小型合集执行抽样下载。
- 用 FFprobe 验证 MP4、MP3、FLAC、原始音频和 WAV 的文件有效性、编码和时长。
