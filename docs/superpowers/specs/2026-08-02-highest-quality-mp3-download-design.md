# 最高音质 MP3 下载功能设计

## 目标

在保留现有 YouTube/Instagram 视频批量下载行为的基础上，增加音频下载模式。音频模式选择源站可获取的最高质量音轨，使用 FFmpeg 转换为 MP3，并同时支持 Web 与命令行入口。

## 产品边界

- Web 页面在现有视频区块下方增加独立的 MP3 音频下载区块，不共用输入框。
- 命令行不带选项时仍下载视频；传入 `--audio` 时下载 MP3。
- 交互式命令行启动时选择视频或音频，默认视频。
- 视频与音频均支持混合输入 YouTube 和 Instagram 链接。
- 每个批次最多并发 3 个任务，并保持结果顺序；Web 同一时刻只允许一个活动批次。
- 输出继续保存在 `downloads/`。

## 架构与数据流

`downloader.py` 继续作为 CLI 和 Web 的共享下载核心。新增 `video`、`audio` 两种媒体类型，并为 `_build_ydl_options()`、`download_video()`、`download_tasks()` 增加默认值为 `video` 的 `media_type` 参数，从而保持现有调用兼容。

音频模式使用 yt-dlp 的 `bestaudio/best` 选择器，再通过 `FFmpegExtractAudio` 输出 MP3，品质设置为 yt-dlp/FFmpeg 的最高 VBR 等级。这里的“最高音质”表示优先选取源站可获取的最高质量音轨；有损 MP3 转码不能提升源音轨的真实质量。

Web 继续使用 `/api/download`。请求体增加 `media_type`，仅接受 `video` 或 `audio`。批次记录媒体类型并将其传给下载核心，进度仍通过现有 `/api/batch/<batch_id>` 轮询。

## 文件与结果

- YouTube 视频保持 `标题.扩展名` 命名。
- Instagram 视频保持 `标题 [内容ID].扩展名` 命名。
- YouTube 音频输出为 `标题.mp3`。
- Instagram 音频输出为 `标题 [内容ID].mp3`。
- 输出路径解析同时支持 MP4 和 MP3 后处理结果。
- 视频结果保留分辨率、帧率、视频编码和音频编码。
- 音频结果显示平台、标题、格式、音频编码、文件大小和保存路径，不显示分辨率或帧率。

## Web 交互

现有视频卡片保持不变。其下新增“MP3 音频下载”卡片，包含说明、独立多行输入框、“下载最高音质 MP3”和“清空输入”按钮，并使用与视频区块相协调但可区分的强调色。

两个区块共用下方任务列表。任务标题根据当前批次显示视频或 MP3 音频；任一批次运行期间，两个区块的输入和提交按钮均禁用，完成后恢复。两个输入框各自保留内容，不会因另一区块提交而被清空。

## 命令行交互

- `python main.py URL...` 下载视频。
- `python main.py --audio URL...` 下载 MP3 音频。
- 交互模式先询问下载类型，直接回车或选择 `1` 下载视频，选择 `2` 下载音频。
- 汇总标题、成功提示和结果字段随媒体类型变化。

## 错误处理

- Web API 对非法 `media_type` 返回 HTTP 400。
- URL、Cookie、重试和平台错误处理沿用现有行为。
- FFmpeg 缺失或转码失败时明确说明 MP3 转换依赖 FFmpeg，并将任务标记为失败。
- 源内容没有音轨时返回清晰的音频流错误。
- 单个任务失败不影响同一批次的其他任务。

## 测试与验收

- 单元测试覆盖音频格式选择器、FFmpeg 后处理器、MP3 输出路径和命名。
- 单元测试覆盖媒体类型在批量核心中的传递、并发上限、结果顺序与异常隔离。
- Flask 测试覆盖默认视频、音频批次和非法媒体类型。
- CLI 测试覆盖 `--audio` 与默认视频行为。
- 页面测试覆盖两个独立输入区、正确请求类型、运行互斥和按媒体类型渲染结果。
- 最终运行完整单元测试和 `compileall`，使用 Flask 测试客户端验证状态流，并在本地浏览器完成交互和视觉检查。
- 使用公开短视频执行一次真实 MP3 下载，通过文件扩展名、文件存在性和 FFprobe 音频信息验收；测试产物保留在 `downloads/` 供用户检查。
