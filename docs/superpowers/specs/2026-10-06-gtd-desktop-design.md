# GTD 桌面版设计（用户已确认）

## 目标与交付

用户要求：把当前 GTD 的全部功能做成可直接运行的桌面程序，macOS 和 Windows 都需要；风格可重新设计，参考 https://github.com/MarkYang44/LMU-Stintrix。

目标版本：macOS Apple Silicon `.app`（本机 arm64 可验证）及 Windows 10/11 x64 便携 ZIP（含 GTD.exe 与运行文件）。macOS Intel 单列为后续目标，不用 arm64 包冒充通用包。保留源码 Web 与 CLI 入口。终端用户无需安装 Python、执行 pip 或启动开发服务器。

参考项目的事实：当前公开 README/requirements-build.txt 使用 PyInstaller，便携目录必须完整保留；视觉包括炭黑/暖灰、黄绿强调、切角面板、中英文和本地偏好。本项目只参考其结构与视觉，不引入其遥测功能或第三方生成器。

## 方案选择

推荐：PySide6 QtWebEngine 原生窗口 + 原有 Flask/Jinja/JavaScript 功能 + PyInstaller。Qt 携带一致的网页渲染能力，独立侧栏和工具栏提供桌面体验；保留成熟下载核心。代价是包含 Chromium、媒体工具的包较大。

替代一：pywebview + 系统网页引擎，体积较小；Windows 需要 WebView2 运行环境，需单独处理安装或携带。
替代二：像参考项目那样把每个功能重写为原生 Tk 页面；大量重写合集选择、字幕状态、图鉴、比较、轮播及策略交互，首版更容易丢失已有行为。

## 功能清单（逐项验收）

1. YouTube / Instagram / Bilibili 混合链接识别、分享文本、标准/极速下载。
2. 合集、播放列表及分 P 预览选择，已有条目数量与输入限制保持有效。
3. MP4 / MKV 视频、字幕、自动字幕、Bilibili 弹幕及原有真实状态提示。
4. MP3 V0 / 源 FLAC / 原始音频 / WAV PCM、封面写入与兜底封面。
5. 本地上传/拖放视频提取音频、上传进度、处理进度与结果保存。
6. 共享并发、平台并发限制、任务进度、取消、重试、重新下载、失败批次重试、SQLite 历史恢复与中断状态。
7. 输出目录输入/原生选择、Cookie 文件配置、能力检测、结构化错误与脱敏日志。
8. 使用说明、全局中英文/深浅主题、原首页彩蛋与 Designed by Mark Yang。
9. LMU 冠军档案、18 条赛道/24 台车型的现有完整图文、推荐、搜索筛选、收藏、最多三项比较、图片轮播、燃油及进站策略、内容更新差异、每周赛历。
10. 赛历继续人工录入/校验/发布；桌面设置提供本地 JSON 导入入口，复用现有原子发布和备份逻辑。没有自动联网更新或虚构赛事字段。
11. CLI 模式保留原交互/参数行为，冻结入口提供显式 CLI 启动方式及使用说明，桌面关闭不会误操作源码实例。

## 架构与界面

- 桌面入口负责生命周期，启动只绑定 127.0.0.1 的内部服务，不占用用户原有 8233 服务。使用固定的桌面专用候选端口与独立用户浏览器 profile，保证网页 localStorage 偏好稳定；端口被外部程序占用时明确提示，避免加载错误服务或悄悄换 origin 丢失收藏。
- 保留原 Flask API、下载执行和任务模型；桌面层负责菜单、窗口、外链交给默认浏览器、原生目录选择及保存下载结果。
- 左侧栏目：下载中心、本地音频、LMU 工具、任务/设置/帮助入口。下载中心内部仍有独立视频/音频区域。LMU 下保留指南、档案、图鉴、策略、赛历、更新全部入口。
- 深色炭黑、浅色暖灰、黄绿强调、切角卡片；正文优先可读性，减少花体标题。中英文、主题切换、键盘访问与缩放需贯穿所有页面。保留署名及现有品牌图标。
- 升级保持用户数据；退出有运行任务时提示用户，确认退出后请求取消并清理自有线程/媒体子进程。错误弹窗给可执行建议和日志位置。

## 资源与可写数据

引入统一路径模块，区分只读包资源与可写用户目录。网页模板、静态资产、内容快照、文档和封面纳入资源清单；冻结运行时不向 `.app` 或 `_internal` 写入。

macOS 用户数据：~/Library/Application Support/GTD；Windows：%LOCALAPPDATA%/GTD。历史、日志、上传缓存、偏好、Cookie 与人工赛历放于用户目录；默认下载放用户 Downloads/GTD，允许原生选择其他位置。首次启动复制公共种子内容，只在目标不存在时写入。原项目历史/收藏/Cookie 不自动复制；提供明确用户选择的导入方式，原数据不删除或改写。

FFmpeg、ffprobe、aria2c、Node.js 按平台架构携带，启动时仅为 GTD 进程调整工具路径。不能依赖 Homebrew、系统 Python 或用户 shell PATH。Bilibili 极速、YouTube JS、MKV 封装、音频处理全部通过打包工具验收。工具来源和许可证随包附带，非公开 Cookie、下载文件、任务历史、日志、venv、测试文件不进入发布包。

桌面服务仅接受自有 profile/会话访问，限制 Host/Origin，变更类请求附带桌面会话凭据；外部网页不得调用下载或文件接口。原 Web/CLI 的行为不因桌面入口启用而改变。

## 构建及验证

固定桌面和构建依赖；统一构建脚本/资源清单，产物 ZIP、SHA256 和必要第三方许可。macOS 本机实际构建、移出源码目录后启动测试；Windows 必须在 Windows runner/实体机独立构建及运行，macOS 不能交叉生成可靠的 Windows PyInstaller 包。

测试包括已有单元/JavaScript/浏览器回归；路径与持久化、端口占用、生命周期、外链/结果下载、各公开路由资源、Native folder picker、真实短媒体处理、脱离源码和系统媒体工具的冻结冒烟检查。联网平台成功率受真实站点和用户 Cookie 权限影响，验证报告区分本地处理通过与外站访问情况。

Windows 构建工作流可先在本地准备；远程推送、触发 GitHub 构建或发布 Release 需在实现和检查完成、具体变更可审阅后由用户授权。不把构建脚本称作已经交付的 EXE。

应用签名/公证需要有效开发者证书；初次本地包可未签名或仅临时签名，交付说明据实记录。不绕过系统安全提示，不冒充已公证安装包。
