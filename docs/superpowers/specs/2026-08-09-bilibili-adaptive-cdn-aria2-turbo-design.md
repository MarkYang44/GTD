# Bilibili 自适应 CDN 与 aria2 极速模式设计

## 目标

在保留现有 YouTube、Instagram 行为、最高质量格式选择、Cookie、文件命名和并发边界的前提下，进一步改善 Bilibili 视频与 MP3 音频下载速度：

- 小文件继续使用已验证稳定的 yt-dlp 原生分块策略，避免额外测速开销。
- 大文件从 Bilibili 返回的主 CDN 与备用 CDN 中选择当前网络下最快的可用节点，并自适应选择分块大小。
- 为 Web 视频区、Web 音频区和 CLI 提供显式、可选的 aria2c“极速模式”。
- CDN 测速或 aria2c 失败时自动回退到现有标准下载路径，不要求用户重新提交。

## 非目标

- 不修改或猜测 Bilibili CDN 域名，只使用平台响应中实际提供的候选地址。
- 不绕过登录、会员、版权、地区或平台风控限制。
- 不保证固定百分比的速度提升；实际吞吐量仍取决于 Bilibili CDN 分配和当前网络路由。
- 不在应用启动时自动安装系统依赖，也不让 aria2c 成为标准模式的必需依赖。
- 不改变 YouTube 或 Instagram 的下载器、格式、进度展示和网络参数。

## 已确认基线

- 项目使用 yt-dlp 选择 Bilibili `bestvideo+bestaudio/best` 或 `bestaudio/best`，视频最终合并为 MP4，音频最终转换为最高 VBR 品质 MP3。
- Bilibili 标准模式当前使用 10 MiB `http_chunk_size`。
- 项目最多同时执行 3 个任务，其中最多同时执行 2 个 Bilibili 任务。
- 现有 Web 标准模式展示实时速度、百分比和 ETA。
- 当前 yt-dlp Bilibili 提取器只将主媒体 URL 放入格式结果；项目需要以实例级适配器保留响应中的备用 URL，不能通过并发不安全的全局补丁实现。
- yt-dlp 的 aria2c 外部下载流程不能稳定提供与原生下载器等价的中途进度回调，因此极速模式采用简化状态展示。

## 下载策略

### 模式定义

公共下载接口增加 `speed_mode`：

- `standard`：默认值，使用 yt-dlp 原生 HTTP 下载器。
- `turbo`：仅对 Bilibili 任务尝试 aria2c；同一批中的 YouTube 与 Instagram 仍按标准模式执行。

未提供该字段的现有 Web、CLI 或 Python 调用全部按 `standard` 处理，从而保持向后兼容。

### 50 MiB 阈值

先用同一个 yt-dlp 实例提取并完成格式选择，但不开始媒体下载。任务大小取实际选中流的 `filesize` 或 `filesize_approx`：

- 视频任务计算所选视频流与音频流的合计大小。
- 音频任务只计算所选音频流大小。
- 合计不超过 50 MiB 时，直接使用 10 MiB 固定分块，不运行 CDN 或分块测速。
- 合计超过 50 MiB 时，运行自适应 CDN 与分块测速。
- 任一必要大小未知、非正数或格式结构无法识别时，按小文件路径处理，使用原始 URL 和 10 MiB 固定分块。

预提取结果会直接交给后续 yt-dlp 下载与后处理阶段，不为测速重复调用视频信息接口。

### 候选 CDN 捕获

新增项目内的 Bilibili 提取适配器，继承当前安装版本的 yt-dlp Bilibili 提取器，并只扩展格式结果：

- 保留 yt-dlp 生成的主 `url`、格式 ID、编码、清晰度和文件大小等字段。
- 从同一条 DASH 视频流或音频流的 `baseUrl`、`base_url`、`url` 与备用 URL 字段中提取有效 HTTPS 地址。
- 去重后将候选地址保存在项目专用的内部格式字段中。
- 适配器只注册到当前 `YoutubeDL` 实例并覆盖该实例的 Bilibili 提取器，不修改 yt-dlp 安装文件，也不做进程级 monkey patch，因此两个 Bilibili 任务可以安全并发。
- 若 yt-dlp 更新导致提取器结构不兼容，适配器返回原始格式结果，下载自动回到主 URL。

### CDN 测速

大文件任务对所选视频流和音频流的候选地址进行以下处理：

1. 按主机名分组，并优先保留主 URL 所在主机。
2. 每个任务最多测试 4 个不同的、由 Bilibili 返回的 CDN 主机。
3. 每个主机只选择一条代表性媒体 URL，发起约 512 KiB 的 HTTP Range 请求。
4. 测速复用当前 yt-dlp 实例的 Cookie、请求头和网络会话；响应字节只计时并丢弃，不落盘。
5. 仅接受有效的部分内容响应；超时、403、412、签名失效、Range 不受支持或长度异常均记为该候选失败。
6. 以完成有效样本的实际吞吐量选择最快主机。所选视频流或音频流存在该主机对应 URL 时使用它，否则该流继续使用自己的主 URL。

测速使用短连接与读取超时，不让单个失效候选长期阻塞任务。完整带签名 URL、Cookie 和敏感请求头不写入日志或 Web 状态。

### 自适应分块

选出 CDN 后，在一条代表性媒体流上比较：

- 当前稳定值：10 MiB；
- 小分块候选：4 MiB。

两个样本均使用 Range 请求并校验有效响应，以实际吞吐量较高者作为该任务的原生 `http_chunk_size`。连同最多 4 次 CDN 采样，首次大文件测速的计划流量上限约为 16 MiB。若分块测速任一侧失败，则保留 10 MiB。

### 30 分钟内存缓存

新增线程安全的进程内 TTL 缓存：

- 键由已去重、排序后的候选 CDN 主机集合组成。
- 值包含最快主机、最佳分块大小、测量时间和有效期。
- 有效期为 30 分钟。
- 命中缓存时直接应用结果，不重复发起 CDN 或分块测速。
- 缓存访问加锁；同一候选集合并发首次出现时只允许一个任务测速，其他任务等待并复用结果。
- 缓存只存在内存中，服务重启后自然清空。
- 缓存中的主机不再出现在当前所选流候选地址中时，不强行改写 URL；该流使用主 URL。

## aria2c 极速模式

### 可用性与配置

项目通过 `shutil.which("aria2c")` 检测本机能力，并向 Web 前端返回布尔能力状态。设计文档最终确认并形成实施计划后，在用户授权下通过 Homebrew 执行 `brew install aria2`；应用本身不会静默安装依赖。

极速模式只改变 Bilibili 媒体流传输方式，候选 CDN、Cookie、格式选择、文件命名、合并和 MP3 转换仍由项目与 yt-dlp 管理。aria2c 使用保守参数：

- 每个任务最多 4 路连接；
- 同一服务器最多 4 路连接；
- 最小分片大小 1 MiB；
- 继续服从项目“最多 3 个总任务、最多 2 个 Bilibili 任务”的外层并发边界。

因此最坏情况下最多有两个 Bilibili 极速任务各使用 4 路媒体连接，不额外提升任务级并发。

### 降级

- aria2c 在提交前不可用：Web 极速开关禁用并显示“未安装 aria2c，当前使用标准模式”；CLI 使用 `--turbo` 时给出中文提示并按标准模式继续。
- aria2c 启动失败、返回非零状态、产生无效临时文件或媒体传输失败：清理该次未完成文件，在同一任务中自动重新使用 yt-dlp 原生标准模式。
- 降级重试复用已选 CDN 与分块结果；若该 CDN 本身返回 403、412 或签名失效，则恢复原始主 URL 与 10 MiB 分块。
- 一个任务只产生一次最终 `completed` 或 `failed` 事件，降级过程不会重复累计批次完成数或失败数。

## Web 体验

### 独立开关

- 视频下载区增加一个“极速模式”开关，只影响该区本次提交的视频批次。
- 音频下载区增加一个“极速模式”开关，只影响该区本次提交的 MP3 批次。
- 两个开关互不共享状态，也不改变现有的独立输入框。
- 请求体增加 `speed_mode: "standard" | "turbo"`。
- 批次和任务状态记录请求模式、实际模式以及是否发生降级，便于前端提示和排查。

### 能力状态

新增只读能力接口，至少返回 `aria2c_available`。页面加载时获取该状态：

- 可用时允许用户打开极速模式。
- 不可用时禁用两个开关，并在开关附近显示明确提示。
- 能力接口异常时按不可用处理，不影响标准下载。

### 进度状态

- 标准模式继续显示实时速度、百分比和 ETA。
- Bilibili 极速模式从下载开始到媒体流完成期间显示“高速下载中”，不显示不可靠的精确速度、百分比和 ETA。
- 进入 FFmpeg 合并或 MP3 转换阶段后沿用现有“正在处理文件”语义。
- 若极速模式降级，任务卡显示“极速模式不可用，已切换标准模式”，随后恢复标准模式实时进度。
- 混合批次中的 YouTube 与 Instagram 任务始终显示现有标准进度。

## CLI 体验

命令行解析增加独立 `--turbo` 标志，并与现有 `--audio` 正交组合：

```bash
venv/bin/python main.py --turbo "https://www.bilibili.com/video/BV..."
venv/bin/python main.py --audio --turbo "https://www.bilibili.com/video/BV..."
```

交互式模式在媒体类型选择后询问是否启用极速模式，直接回车默认关闭。下载汇总可显示实际采用的模式和是否降级，但不显示完整 CDN URL。

## 接口与状态传播

`speed_mode` 沿调用链显式传递：

1. Web `api_download()` 或 CLI 参数解析；
2. Web `_create_batch()`、`_run_downloads()`；
3. `download_tasks()`；
4. `download_video()`；
5. Bilibili 下载计划解析和 yt-dlp 选项构建。

下载结果增加非敏感字段：

- `speed_mode_requested`；
- `speed_mode_used`；
- `turbo_fallback`；
- `cdn_host`，仅为主机名；
- `http_chunk_size`。

Web 对 `speed_mode` 做严格字符串和枚举校验；未知值返回 HTTP 400。Python 公共入口同样校验，防止静默接受拼写错误。

## 错误与安全边界

- CDN 探测遇到 403、412、超时或无有效候选时回到主 URL，不将测速失败直接升级为任务失败。
- 只对 Bilibili 大文件运行探测；YouTube 与 Instagram 不读取、缓存或改写 CDN 地址。
- 候选 URL 必须是 HTTPS 且来自当前提取响应；不接受用户输入的媒体 CDN 地址。
- 日志、错误消息、批次状态和测试快照只记录 CDN 主机名，不记录 URL 查询参数。
- Cookies 文件继续由现有 `_find_cookie_file()` 选择，不读取或复制到前端。
- aria2c 未完成文件只清理本任务能够明确识别的临时目标，不对下载目录执行宽范围删除。
- 任何适配器、缓存或极速模式异常均被限制在当前任务内，不影响其他并发任务。

## 自动化测试

### 策略与适配器

- 视频任务正确合计所选视频流与音频流大小，音频任务只计算音频流。
- `<= 50 MiB`、`> 50 MiB`、未知大小和无效大小分别进入正确路径。
- Bilibili 适配器保留主 URL 和备用 URL，去重并拒绝非 HTTPS 候选。
- 适配器结构不兼容时返回原格式，不影响标准下载。
- 每个任务最多测试 4 个不同主机，每个主机最多采样 512 KiB。
- 正确选择最快成功候选，并在候选全部失败时保留主 URL。
- 4 MiB 与 10 MiB 分块比较正确，任一测试失败时回到 10 MiB。

### 缓存与并发

- 同一主机集合在 30 分钟内命中缓存，过期后重新测速。
- 候选集合顺序变化不影响缓存键。
- 并发首次访问同一键时只执行一次测速。
- 不同候选集合互不污染，服务级缓存清空后重新测速。
- 全局最多 3 个任务、Bilibili 最多 2 个任务的既有测试继续通过。

### aria2c 与降级

- 检测 aria2c 可用和不可用状态。
- 标准模式不配置外部下载器。
- 极速模式使用预期的 4 路连接参数。
- aria2c 不可用时 Web 禁用、CLI 提示并使用标准模式。
- aria2c 非零退出或无效输出触发一次标准模式重试。
- 降级任务只产生一次终态事件并清理明确归属的临时文件。

### Web 与 CLI

- Web 接受 `standard` 和 `turbo`，拒绝非字符串或未知值。
- 视频与音频极速开关独立，分别发送当前区块的模式。
- 能力接口返回布尔状态，异常时前端安全禁用开关。
- 标准、极速、降级三种任务状态显示正确。
- CLI `--audio`、`--turbo`、两者组合及默认参数解析正确。
- 未传 `speed_mode` 的现有调用保持标准模式。

### 回归检查

- 运行全部 Python 单元测试。
- 运行 Python `compileall`。
- 对模板内 JavaScript 执行语法检查。
- 运行 `git diff --check`。
- 验证 Bilibili Cookie 不进入 Git 变更、日志或测试输出。

## 真实网络基准与验收

使用当前网络和有效 Bilibili Cookie，选择一组小于 50 MiB 和一组大于 50 MiB 的合法样本：

1. 小文件验证不会发生测速，标准模式无额外启动延迟。
2. 大文件分别运行现有固定策略、自适应标准模式和 aria2 极速模式。
3. 每种模式至少运行 3 次，以媒体传输阶段的中位吞吐量和中位耗时比较，不把 FFmpeg 时间计入网络速度。
4. 记录候选主机名、被选主机、分块大小、实际模式、是否降级和耗时，不记录带签名 URL。
5. 使用文件大小与 FFprobe 验证 MP4 可播放、音视频流完整；使用 FFprobe 验证 MP3 编码和时长。

功能验收条件：

- 自适应策略能够在受控测试中选择当次探测最快的可用 CDN，缓存命中时不重复测速。
- 小文件继续走 10 MiB 固定分块，且不承担 CDN 探测流量。
- 极速模式能够无损完成视频与 MP3 输出；aria2c 故障时能自动完成标准模式降级。
- YouTube、Instagram、标准 Web 实时进度、文件命名、Cookie 和并发边界无回归。
- 不将特定速度增幅作为跨时间、跨地区保证；实际基准结果如实写入实施报告。
