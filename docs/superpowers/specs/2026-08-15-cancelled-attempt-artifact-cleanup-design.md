# 取消任务私有残留清理设计

## 问题与证据

Bilibili 标准模式任务被取消后，yt-dlp 会把部分文件直接留在用户选择的目标目录，而不是 `.attempts/<id>/` 临时目录。实际残留的源封面 `.jpg` 和未完成分片 `.f100026.mp4.part` 带有相同的 ` [.__mvd_<id>]` 私有任务标记；随后重新下载成功生成了不带该标记的最终 MP4，因此用户看到三个文件。

现有 `cleanup_attempt_workspace()` 只删除 `.attempts/<id>/`，没有回收目标目录中属于同一尝试的旁路产物。

## 已确认方案

采用精确任务标记清理：每次尝试结束时，在删除工作目录的同时，仅删除目标目录中包含该尝试完整 ` [.__mvd_<id>]` 标记的文件或符号链接。

- 清理取消、失败、回退及成功后遗留的 `.part`、格式分流、缩略图和下载器状态文件。
- 不按标题或扩展名做模糊扫描。
- 不删除不带当前完整标记的最终媒体、其他任务文件或用户已有文件。
- 保持现有下载、重试、命名和封面处理顺序不变。
- 清理继续采用 best-effort 语义；清理错误不覆盖原始下载结果。

## 实现边界

扩展 `output_files.cleanup_attempt_workspace(workspace)`，沿用现有接口：

1. 校验 `workspace` 的直属父目录名为 `.attempts`。
2. 校验工作目录名只包含任务 ID 允许的 ASCII 字符。
3. 从工作目录名构造完整私有标记 ` [.__mvd_<id>]`。
4. 仅遍历目标目录的直属条目，并 `unlink()` 名称包含完整标记的普通文件或符号链接。
5. 删除工作目录，并在空闲时移除 `.attempts`。

下载器现有普通下载与 Bilibili 多尝试路径都已在 `finally` 调用该接口，因此不新增重复清理调用。

## 测试与验收

- 回归测试先复现当前失败：目标目录中的私有 `.jpg` 和 `.f100026.mp4.part` 在清理后仍存在。
- 修复后上述残留消失。
- 同名最终 MP4、无关 `.part`、其他任务标记文件和其他任务工作目录必须保留。
- 非 `.attempts/<id>` 路径继续拒绝清理。
- 运行 `output_files`/下载器定向测试、完整 unittest、compileall 和 `git diff --check`。
- 不自动删除用户目标目录里已经存在的历史残留。
